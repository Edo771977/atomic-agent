# Fusion completion request budgets

Status: current
Owner: src/runtime/

`llm.runMode.fusion.turnBudgetUsd` shares one admission ledger across a parent turn's planning completions, bound workers, judge and escalation calls. [Turn state](../../tools/fusion/turn-budget.ts) separates held request reservations, settled request charges and carried/external spend. Existing worker usage callbacks keep their display totals; runtime-owned callbacks identify already-accounted requests so the ledger does not charge them twice. Resumed checkpoint spend remains a separate additive charge. Worker ownership is installed and cleared with the worker's approval policy, including failures and escalation replacements; a worker bound to an older parent turn cannot spend from a newer one.

[The link attempt](../llm-link-attempt.ts) creates a [request scope](../request-budget.ts) after preparing the prompt for the provider actually serving the attempt. OpenAI-compatible HTTP invokes that scope immediately before **each physical send**, including internal retries, schema/temperature repairs and fallback attempts. The hook sees the converted messages, tools and model parameters that will be serialized. An override cannot raise the output ceiling after admission: the hook clamps the final output fields to the minimum explicit request/turn/provider ceiling, or a known model window when no ceiling was supplied (the resolved model carries no separate output limit; a provider entry's `maxOutputTokens` is the place to set a smaller one). It clamps whichever of `max_tokens`/`max_completion_tokens` the body already uses; when the body has neither it writes the wire model's profile field (`max_completion_tokens` for OpenAI reasoning models), never both. A default-resolved model without an explicit ceiling is refused under a USD cap. A priced adapter without physical-send support is refused under a USD cap. No cap preserves the previous request shape and retry behavior.

Reservation assumes no prompt-cache discount. It bounds input by the serialized UTF-8 bytes of the final body plus a fixed framing allowance (no tokenizer emits more than one token per text byte), not by the model context window, which would reserve a full window for every short request, and uses the highest configured input/cache-read/cache-write rate. It reserves the complete output ceiling, including reasoning counted by the provider in its output token limit, and accounts for multiple requested completions. Unknown paid pricing, an unverifiable output ceiling, or an inference override that bypasses physical-send authorization refuses the request before sending. Explicit local runners and subscription CLI plans remain unpriced; their existing step/request/token restrictions still apply. This policy covers the runtime's text completions, not separate embedding, image, video or external-tool bills. Embedders that call providers outside the runtime seam must wire equivalent admission; the standalone delegate's legacy usage callbacks only observe completed spend.

On completion, reported cost wins, otherwise reported usage is priced normally. Unused held allowance is released. Definite pre-generation rejection statuses (400/401/402/403/404/405/413/415/422/429) and the overload answers 503/529, which providers return instead of generating and do not bill, release the hold. A send that fails before any connection exists (`ECONNREFUSED`, `ENOTFOUND`, `EAI_AGAIN`, reported through the optional `onSendFailed` hook) also releases it, so a retry or the surfaced connection error is not replaced by a budget refusal. An ambiguous dispatch failure (a reset, timeout, TLS/socket error or any other transport errno, which can follow a delivered body), 408, 500/502/504 and other 5xx, cancellation or abandoned stream without final usage settles the conservative upper bound and releases the hold; a retry needs a new reservation. A setup failure before sending has no charged reservation. These are admission estimates under configured price and provider token-limit assumptions; they do not guarantee a vendor invoice, which can include different prices, provider-side routing or unreported charges.

The capped receipt's `spentUsd` is the accounted amount; its optional `conservativeUsd` identifies the part settled without final usage. That amount may overstate the eventual bill. A parent turn deactivates its request policy at `turn_finished`, so subsequent background work does not inherit a completed turn's deadline or allowance.

OpenAI adapters preserve incomplete token-report provenance even when display counters normalize missing values to zero. Missing or partial unary/SSE usage settles the reserved bound; explicitly reported zero token counts or zero billed cost remain trustworthy zero charges.

A localhost/private-network address does not establish free inference: compatible gateways require known prices, including explicitly configured zero rates for a free endpoint. Only `llama-server` and `subscription-cli` kinds are unpriced by contract. Any reported dollar cost is still charged, even from those kinds; a contradictory bill cannot disappear from the ledger.

Foreground compaction, smart approval and query rewriting pass an explicit `budgetOwnerSessionId` separate from their `compaction:`, `risk:` or `rewriter:` routing/breaker partition. The seam uses that owner only for active-turn money and deadline admission; it never infers ownership by stripping a prefix. Background rolling compaction explicitly opts out, and post-turn reflection, naming and consolidation remain independent background work rather than inheriting a completed turn's policy.

HTTP error diagnostics retain the combined deadline/cancellation signal after response headers arrive. Their body reads are limited to 64 KiB, cancel the reader on abort or clipping, and also retain the provider request timeout; a stalled non-2xx body cannot keep a capped request alive past its deadline. A 5xx without final usage still carries its conservative dispatch charge.

`turnTimeBudgetMs` also applies to ordinary unary/stream planning calls before and after fan-outs. Each serving request combines the remaining turn deadline with its caller's signal and clears its timer on completion, error or stream abandonment. The fan-out retains its shared deadline through post-wave checks, syntax validation and judging, then reports the final settled spend and elapsed time. Host checks and providers must honor cancellation; the runtime cannot forcibly stop arbitrary code that ignores its signal.
