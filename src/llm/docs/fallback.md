# Reliability and provider fallback

Status: current
Owner: src/llm/

## Responsibilities

Transport retry handles transient request/open failures: at most three attempts with jittered backoff, stretched to a provider's `Retry-After` up to 5 s. A cooldown longer than that is not retried in place (it would only spend requests against the same limit); the error goes up so the turn's outage wait honours the full hint within `agent.providerWait.maxWaitMs`, or the person's fallback link answers (ATO-483). A switch to a fallback link is always said in the turn: the `provider_switched` event carries the failure-catalog cause and the fallback model, and hosts show `falloverSentence` ("OpenRouter is rate-limited, switched to Gemini (gemini-2.5-flash)."; the SSE `atomic.provider_switched` frame's `notice`). Beyond that, parse recovery belongs to the step executor. Targeted credit-limit and structured-output repairs modify only their narrowly identified refusal. Do not broaden these into retries of arbitrary deterministic errors.

The chain holds only links the person picked: the active provider plus `llm.fallback.chain`. The local llama-server provider is appended only when `llm.fallback.appendLocal` is true (default false, ATO-349/ATO-892): a cloud error must surface as its own reason (`failure-catalog.ts`: phrase plus one action, `fix-key` for a refused key) rather than a silent switch to, or a wait on, a local model nobody chose.

The daily spend ceiling (`llm.costTracking.dailyLimitUsd`, ATO-649) refuses a paid link before anything is sent ([error](../reliability/spend-limit-error.ts)): in the seam's per-attempt hook once today's persisted total is at or over it, and per physical send through the request budget's daily hold ([request budgets](../../runtime/docs/request-budgets.md)). `llm.costTracking.onDailyLimit` decides what happens once the ceiling is exhausted: `"stop"` (default) does not advance, so the turn ends on "Daily cloud limit reached: $X of $Y. Cloud calls are paused until tomorrow." (failure cause `daily_limit_reached`) and every later paid call that day is refused the same way; `"local"` advances to the next link, the local model when the chain has one, and the switch notice says so (`cause: "spend-limit"`). The day is the UTC calendar day starting at `llm.costTracking.dailyResetHourUtc` (0-23, default 0: with 6, the total resets at 06:00 UTC). The total lives in `daily-spend.json` in the state directory, shared by every process on it and written durably (flushed tmp file, atomic rename, directory flush) ([store](../../session/daily-spend.ts)); there is no cross-process lock, so two processes can lose a racing write or together overshoot the ceiling by their in-flight holds. Only `llama-server` and `subscription-cli` links are free and never refused, the same rule as the turn budget: any other kind is counted and capped even on a loopback, LAN or Tailscale address, which can be a paid gateway.

A turn the model router routed (`llm.router`, ATO-483) runs on that session's chain with the routed provider put first for the turn (`setTurnPrimary`), the configured links after it: a failure of the routed provider falls over to the next link like any primary's. Changing that head drops the session's sticky override, as a new primary does.

Below the ceiling, a physical request whose minimum output bound cannot fit the positive remaining allowance carries `wouldExceed`. This request-fit refusal advances through the configured chain under either daily-limit action, so a cheaper provider can answer. Every attempt still performs the normal daily and turn reservations; actual exhaustion obeys `onDailyLimit: "stop"`, turn-budget refusals do not advance, and pinned requests keep their single provider. Neither request-fit nor exhaustion refusals increment provider failure counters or arm cooldowns. The request-fit switch has `cause: "spend-allowance"` and failure `daily_allowance_insufficient`; its notice names the remaining allowance rather than claiming cloud calls are paused until tomorrow. If no configured link can serve, the budget refusal remains the final error.

The fallback breaker reads live chain configuration and partitions mutable state by session. Advancing past a failed link skips links still in cooldown, unless every remaining link is cooling (then the first is tried as a last resort); a link skipped that way is tried before the turn gives up, soonest cooldown end first. Memory runners use distinct session identities; pinned worker turns bypass fallover. An appended local fallback is still omitted when no model weights are available, avoiding a wait for a daemon that cannot start; [availability](../../runtime/local-link-availability.ts) owns this check. Provider selection/probing is lazy and owns no periodic timer. A changed active provider affects subsequent resolution rather than a captured boot-time value.

## Streams and transport

Opening/priming a stream can fail over before committed output; an SSE keep-alive comment is not output and does not commit the stream. Once output is committed, restarting risks duplicating visible text or side effects. Cancellation must propagate as cancellation rather than advancing the provider chain.

Fallback completions and chunks carry servedTransport. Parsing and live reasoning detection use the actual serving link, including when a native-tools primary falls back to grammar. The primary's capabilities are not proof of what the fallback served. Cross-provider strict/parallel capability handling and grammar-primary/native-tail payload limitations remain explicit implementation constraints.
